# R-Launcher v2 の画面設計

最終更新: 2026-10-08

## 1. 「AI っぽい」画面とは（調査）

生成 AI に何も制約を与えずに画面を作らせると、学習データで最も多い「無難な平均」に寄る。2025〜2026 年のデザイン系の記事で、繰り返し挙げられている特徴は次のとおり（1 つだけなら問題ないが、まとめて出ると「AI が作った」と見抜かれる）。

| 種類 | 特徴                                                                                                                                |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 色   | 紫〜青のグラデーション。彩度の高い色が同じ強さで並び、主役が無い。どの部品にも違う差し色。真っ白・真っ黒の背景に奥行きが無い        |
| 効果 | すりガラス（glassmorphism）を全面に。ダークモードでの光彩・ネオン・オーラ。意味の無い影                                             |
| 文字 | 何も考えずに Inter。抽象的で大げさな見出し（「体験を次のレベルへ」）                                                                |
| 配置 | 中央寄せの大見出しと上の小さな丸いバッジ。アイコンが上に乗った 3 枚のカード。カードの中にカード。全部同じ余白（どこも p-4 / gap-6） |
| 部品 | 絵文字をアイコン代わりに。意味の決まっていない色付きの点（ステータスドット）があちこちに。丸い「ピル」型のラベルだらけ              |
| 文言 | 「✨」「🚀」、ダッシュ多用、何でも「シームレス」                                                                                    |

主な出典:

- [7 Signs a UI Has Been Vibe Coded（The Fountain Institute）](https://www.thefountaininstitute.com/blog/signs-vibe-coded-ui)
- [AI Slop Web Design: Complete Guide（925 Studios）](https://www.925studios.co/blog/ai-slop-web-design-guide)
- [AI Slop Fonts and Gradients（925 Studios）](https://www.925studios.co/blog/ai-slop-design-tells)
- [Design Systems for AI Coding: Stop Getting Purple Gradients（BrainGrid）](https://www.braingrid.ai/blog/design-system-optimized-for-ai-coding)
- [Why Your AI-Generated UI Looks Like Everyone Else's（Medium）](https://medium.com/@Rythmuxdesigner/why-your-ai-generated-ui-looks-like-everyone-elses-and-how-to-break-the-pattern-7a3bf6b070be)

共通する処方は「流行ではなく、その製品と利用者から色や形を決める」「色・余白・文字の決まりを先に作り、それ以外を使わない」「何を目立たせるかを決め、それ以外は静かにする」。

## 2. この画面の方針

**主役はサーバーと「遊ぶ」ボタン。** ランチャーは遊ぶ前に一瞬開く道具なので、飾らずに、状態がひと目で分かることを優先する。

### 色

- 地の色は Minecraft の素材から取った無彩色寄りの色。ダークは深層岩（#181917 系）、ライトは紙（#f2efe7 系）。純白・純黒は使わない。
- 差し色は **1 色だけ**。利用者が素材の名前で選ぶ: 銅（既定）・草・海晶・レッドストーン・金。紫は入れない。
- 差し色を使ってよいのは「遊ぶ」ボタン、選択中の行の印、フォーカスの枠、進み具合の棒だけ。
- 状態の色（緑・黄・赤）は状態を表すときだけ使い、必ず文字を添える。

### 文字

- 本文は OS の日本語 UI フォント（Yu Gothic UI → Meiryo UI → Hiragino Sans → Noto Sans JP）。Inter は使わない。
- バージョン・人数・遅延・ハッシュなどの数値は等幅（Cascadia Mono → Consolas → BIZ UDGothic）で、桁をそろえる。
- 見出しは左寄せ。サーバー名だけを大きくする（28px）。ほかは 13〜15px の範囲に収める。

### 形と配置

- 角丸は 3px。境界は 1px の線。影は「ダイアログ」だけ。すりガラス・光彩・グラデーションは使わない。
- 左に**サーバーの一覧（行）**、右に**選んだサーバーの詳細**、下に**遊ぶバー**。カードの並べ置きはしない。
- 余白は 4・8・12・20・32px の段階を使い分ける（全部同じにしない）。
- 状態は「稼働中 3/20 人・42ms」のように文字で書く。印は 6px の四角を、稼働中・停止中の区別だけに使う。
- アイコンは設定・ログ・再読み込みなど最小限の線画（自作の SVG）。絵文字は使わない。
- 動きは色の切り替え（120ms）と進み具合の棒だけ。跳ねる動きはしない。

### 背景画像

- 利用者が選んだ画像を、詳細の領域だけに敷く（一覧には敷かない）。上に地の色を 0〜80% で重ねて文字を読みやすくする（ぼかしは使わない）。
- 画像はアプリのフォルダに取り込み（PNG・JPEG・WebP、10MB まで、中身の先頭バイトで形式を確かめる）、専用のスキーム（`rl-bg:`）からだけ読む。

### 文言

- 短く、具体的に。「遊ぶ」「更新して遊ぶ」「Mod をそろえています（3/12）」。
- 失敗したら、何が起きて次に何をすればよいかを書く（「Panel につながりません。インターネット接続を確かめてください」）。
- 「シームレス」「次のレベル」などの飾り言葉、感嘆符、絵文字は使わない。
